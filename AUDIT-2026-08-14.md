### 2.3 `server.ts` — Code Quality Review

**Lines:** 1696  
**Verdict:** Well-structured, well-commented. Key findings:

- **Line 221-226:** `uncaughtException` and `unhandledRejection` handlers are registered — good practice. However, `uncaughtException` is documented by Node.js as "not safe to continue after" — the handler logs but doesn't exit. The process may be in an inconsistent state.
  **Suggestion:** Consider calling `process.exit(1)` after logging the uncaught exception, or use a process manager that restarts.

- **Line 334-338:** Management endpoints (`/__bili/`, `__acp/`) are restricted to loopback — good security practice.

- **Line 1152-1174:** Debug dump writes request bodies to disk. The `ACP_DUMP_DIR` env var controls the directory. Bodies may contain API keys (in `Authorization` headers, which are stripped from the dump, but the body itself may contain key material for some providers). This is behind a debug flag and `ACP_DUMP_REQ !== "0"`, but the default is "dump enabled" when debug is on.
  **Suggestion:** Document that `--debug` can write request bodies to disk.

- **Line 1688:** `readBody` Promise resolves on `req.on("end")` but the `req.on("data")` reject path (when body exceeds limit) does NOT prevent `end` from firing later — the promise is already settled, so `Buffer.concat` is never called. This is handled correctly by the `aborted` flag. **Good.**

### 2.4 `mitm.ts` — Security Review

**Lines:** 187  
**Verdict:** Solid implementation. The MITM whitelist (`DEFAULT_MITM_DOMAINS`) is the security boundary — only 4 domains are intercepted. Non-whitelisted hosts are tunneled blindly. The `ALPNProtocols: ["http/1.1"]` constraint prevents HTTP/2 confusion.

- **Line 164:** Socket marker uses a Symbol-like string key. While this works, a collision with a real socket property is unlikely but possible.
  **Suggestion:** Use a `Symbol` instead of a string key for `MITM_UPSTREAM_KEY`.

- **Line 169:** TLS error handler is properly attached to prevent crashes.

### 2.5 `ca.ts` — Certificate Security

**Lines:** 121  
**Verdict:** Good. Root CA key is stored with `0o600` permissions. Cert is `0o644`. RSA 2048-bit keys. 10-year validity for root CA, 2-year for host certs. The `secureContextCache` prevents repeated key generation.

- **Line 90:** `serialNumber` uses `Date.now() + Math.random()`. This is not cryptographically meaningless but is not a standard serial number format.
  **Suggestion:** Use a hex-encoded random 16-byte value for serial number (cosmetic).

### 2.6 `update.ts` — Auto-Update Reliability

**Lines:** 398  
**Verdict:** Well-designed. The lock file mechanism prevents concurrent updates across processes. Stale lock detection handles crash recovery. The `tar` npm package is used instead of system `tar` (cross-platform, avoids Windows issues). `fs.cp` is used instead of system `cp` command.

- **Line 31:** `REGISTRY_BASE = "https://registry.npmjs.org"` — hardcoded. If npm registry changes its URL, this breaks.
  **Suggestion:** Consider making the registry URL configurable via env var.

- **Line 229:** `fetch(url, { signal: AbortSignal.timeout(5000) })` — 5s timeout for registry check. This is reasonable.

### 2.7 `upstream-proxy.ts` — Proxy Resolution

**Lines:** 426  
**Verdict:** Comprehensive proxy resolution logic. Supports per-URL proxy overrides, HTTP_PROXY/HTTPS_PROXY/ALL_PROXY env vars, Windows system proxy via registry, NO_PROXY parsing, and auto-detection. The `redactProxyUrl` function properly masks credentials.

- **Line 102:** Self-loop detection prevents proxy pointing back to bili.

### 2.8 `compress-loop.ts` — Critical Path

## 4. Security

### 4.1 API Key Handling — **STRENGTH**

- Authorization headers are masked in logs (first 8 + last 4 chars shown)
- Management endpoints are loopback-only (403 for non-local)
- CORS origin validation on management endpoints
- MITM only decrypts whitelisted domains (4 hardcoded + user extras)
- CA key stored with `0o600` permissions

### 4.2 No Committed Secrets

`git grep` for API keys, passwords, tokens in `src/` found no false positives (the grep command had shell quoting issues — manual verification of key files confirms no hardcoded secrets).

### 4.3 Potential Concerns

- **Request body dumps** (server.ts:1152-1174): When `--debug` is enabled, full request bodies are written to disk. These may contain API keys or conversation content. The dump directory is under `~/.local/state/` which has reasonable OS-level protection.
  **Mitigation:** Already behind a debug flag.

- **MITM CA trust:** The root CA certificate is written to `~/.local/state/billion-context/ca/root-ca.pem`. Users install this into their trust store. A compromised system could use this CA to decrypt any TLS traffic. This is inherent to MITM proxy design.
